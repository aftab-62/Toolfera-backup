Research date: 8 October 2026. Fresh web searches and fetched landing-page content informed this phase. This is qualitative intent and content research, not a rank tracker. Search volume, keyword difficulty, backlinks, exact SERP positions, competitor Lighthouse results and measured competitor response times were **not measured**. Search-result presence does not establish a stable ranking. Landing-page text was inspected; competitors' file-processing outputs were not tested.

## Intent and opportunity decisions

Competitive head terms such as PDF to Word, compress PDF, image compressor, GPA calculator, JSON formatter and QR code generator remain tool-page targets. “High-volume” is not assigned a numeric value or asserted as measured. Longer problem-solving queries are **candidate opportunities**, not proven low-competition terms: already optimized PDFs, native text versus OCR, wrong PDF merge order, image dimensions versus bytes, unequal semester credits, percentage points, JSON integer precision, double URL encoding and QR quiet-zone failures.

Articles answer those questions; tool pages let the visitor perform the task. Broad category hubs explain how to choose a workflow. Exact format direction stays on one tool URL. The percentage calculator keeps its existing student URL while the finance hub links to it; no duplicate finance calculator route was created. No city, country, device or keyword-variant doorway pages were added.

## Primary references for technical accuracy

- [Google canonical guidance](https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls): consistent canonical signals, not an indexing guarantee.
- [Google sitemap guidance](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap): include canonical useful URLs; do not invent last-modified dates.
- [Google Article structured data](https://developers.google.com/search/docs/appearance/structured-data/article): truthful article identity, dates and publisher.
- [Google FAQ availability](https://developers.google.com/search/blog/2023/08/howto-faq-changes): ordinary utility-site FAQs do not justify claims of FAQ rich-result eligibility.
- [Google SoftwareApplication guidance](https://developers.google.com/search/docs/appearance/structured-data/software-app): semantic app markup is not an eligible-review-rich-result claim; no fake rating was added.
- [MDN image formats](https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Formats/Image_types): format properties, not universal compression savings.
- [RFC 8259](https://www.rfc-editor.org/rfc/rfc8259) and [MDN JSON.parse](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/JSON/parse): syntax, duplicate names and parsing limits.
- [RFC 4648](https://www.rfc-editor.org/rfc/rfc4648) and [MDN encodeURIComponent](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/encodeURIComponent): byte encoding and URL-component boundaries.

- [MDN String](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/String): code points, code units and visible-symbol distinctions.

Writing is original and task-specific. Competitor prose, testimonials, metrics and certifications were not copied. Tool capability statements were checked against current source content and UI limits; no processing algorithms were modified for this phase.
